## Topic: Learms should be a mastery platform, not a content library only
### Source: Freeman et al., 2014; Dunlosky et al., 2013; McCracken et al., 2001
### Key Finding: Active learning improves STEM outcomes, distributed/practice testing are high-utility learning techniques, and first-year CS students struggle with independent program construction.
### Relevance to Learms: Learms should combine explanations with active coding, debugging, spaced review, and projects.
### Citation: https://doi.org/10.1073/pnas.1319030111 ; https://doi.org/10.1177/1529100612453266 ; https://doi.org/10.1145/572133.572137

## Topic: Learms should localize for Pakistan with evidence confidence labels
### Source: PSEB, 2024; P@SHA, 2025; PTA, 2024; GSMA, 2024
### Key Finding: Pakistan has a growing IT/ITeS export and workforce context, but role-level salary/job claims require current validation; connectivity sources show coverage and usage gaps.
### Relevance to Learms: Show local evidence freshness, confidence levels, low-data UX, and Pakistan-relevant role paths.
### Citation: https://www.techdestination.com/wp-content/uploads/2025/01/PSEB-ANNUAL-REPORT-7_compressed.pdf ; https://www.pasha.org.pk/wp-content/uploads/Skills-Survey-2025.pdf ; https://www.pta.gov.pk/category/chairman-pta-presents-annual-report-2024-to-chairman-of-the-senate-of-pakistan-1169784892-2024-12-18 ; https://www.gsma.com/newsroom/press-release/gsma-highlights-pakistans-digital-progress-and-potential-to-spur-accelerated-economic-growth/

## Topic: Learms should integrate professional practice early
### Source: SWEBOK v4.0; O*NET; Jureczko et al., 2020
### Key Finding: Software development work includes requirements, testing, documentation, maintenance, collaboration, and quality practices; code review supports quality and knowledge transfer.
### Relevance to Learms: Every path should include Git, testing, review, documentation, and security/privacy basics.
### Citation: https://www.computer.org/education/bodies-of-knowledge/software-engineering ; https://www.onetonline.org/link/summary/15-1252.00 ; https://doi.org/10.1049/iet-sen.2020.0134

## Highest-Confidence Product Recommendations

1. Use active learning and project milestones as core structure.
2. Build an error-message/debugging support layer.
3. Use a prerequisite knowledge graph for paths and recommendations.
4. Add spaced retrieval for concepts, commands, and recurring bugs.
5. Support low-bandwidth, text-first, accessible learning UX.
6. Separate Pakistan local-market evidence from global trends.
7. Use private mastery dashboards rather than public shame leaderboards.
8. Include code review, testing, Git, and documentation from early projects.
