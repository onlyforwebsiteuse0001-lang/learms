## Topic: Programming assessment must include construction, debugging, and explanation
### Source: McCracken et al., 2001; Fitzgerald et al., 2008; Becker et al., 2019
### Key Finding: CS1 learners struggle with independent programming, debugging, and error messages.
### Relevance to Learms: Assessments must go beyond multiple-choice and include code-writing, tracing, debugging, and explanation.
### Citation: https://doi.org/10.1145/572133.572137 ; https://doi.org/10.1080/08993400802114508 ; https://doi.org/10.1145/3344429.3372508

## Topic: Peer/code review can be part of assessment
### Source: Jureczko et al., 2020; Salleh et al., 2011
### Key Finding: Code review and pair programming literature support collaboration/feedback when structured.
### Relevance to Learms: Use review rubrics and pair tasks for formative assessment.
### Citation: https://doi.org/10.1049/iet-sen.2020.0134 ; https://doi.org/10.1109/TSE.2010.59

## Assessment Rubric

| Assessment Type | Measures | Failure Mode | Learms Guardrail |
|---|---|---|---|
| MCQ | concept recognition | guessing | explain why wrong answers are wrong |
| Code tracing | mental model | rote syntax | ask prediction before run |
| Small coding task | construction | copy/paste | hidden tests + explanation |
| Debugging task | diagnosis | random trial | bug journal and hypothesis prompt |
| Project | integration | tutorial copying | milestones + oral/project defense |
| Peer review | collaboration | shallow comments | guided rubric/examples |
| Spaced quiz | retention | cramming | distributed schedule |

## Anti-Cheating vs Learning Balance

- For practice, allow hints and retries.
- For certification, require proctored/defended artifacts if stakes are high.
- Use plagiarism checks carefully and explain process.
- AI disclosure should be required for portfolio projects.
