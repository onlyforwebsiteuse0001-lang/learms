## Topic: Choice overload is plausible but must be applied carefully
### Source: Iyengar and Lepper, 2000
### Key Finding: The classic choice-overload study found that larger choice sets can attract attention while reducing action; however, this is not an IT-specific source and later literature includes nuance/replication caveats.
### Relevance to Learms: Learms should reduce visible path overload for beginners, but should not overclaim that all choice is harmful.
### Citation: https://doi.org/10.1037/0022-3514.79.6.995

## Topic: Programming competence requires independent problem solving, not only tutorial completion
### Source: McCracken et al., 2001; Robins et al., 2003; Brown and Altadmri, 2018
### Key Finding: CS education research repeatedly shows that novices struggle with program construction, mental models, strategies, and misconceptions.
### Relevance to Learms: “Tutorial hell” should be reframed as a measurable gap between guided performance and independent transfer.
### Citation: https://doi.org/10.1145/572133.572137 ; https://doi.org/10.1076/csed.13.2.137.14200 ; https://doi.org/10.1145/3160489.3160493

## Topic: Framework learning should follow platform and language fundamentals
### Source: MDN Web Docs, 2026
### Key Finding: MDN provides learning resources around web platform fundamentals such as HTML, CSS, JavaScript, and Web APIs.
### Relevance to Learms: For web learners, framework choice should be delayed until platform basics are usable.
### Citation: https://developer.mozilla.org/en-US/docs/Learn_web_development

## Learms Design Recommendations

| Problem | UI/Path Solution | Evidence Status |
|---|---|---|
| Too many frameworks | show one default path plus alternatives hidden under “compare” | Supported by choice overload broadly; IT-specific evidence pending |

| Framework before fundamentals | prerequisite gates for HTML/CSS/JS/HTTP/SQL | Supported by docs/curricula |
